# P2 firmware build replay forensic — 2026-09-11

## Scope

This is a host-only reproducibility control.  It did not start a VM, create a
tablet patch, change Windows media, or change Android state.

The purpose was to test whether the stored successful P2 firmware can be
regenerated byte-for-byte before interpreting P2.1's earlier DXE failure as a
property of its watchdog code.

generated Build tree were not archived, and a full FD rebuild may also have

a controlled replacement for the archived working P2 FD.

## Deeper FV comparison — 2026-09-12

The earlier whole-FD comparison overstated the practical drift because the
main FV is contained in an LZMA-guided section.  Both images were unpacked
read-only with the same local `LzmaCompress.exe` and compared structurally.

| Check | Archived P2 | Source replay | Result |
|---|---:|---:|---|
| decompressed `FVMAIN` size | 5,410,064 bytes | 5,410,064 bytes | equal |
| inner FFS files | 62 | 62 | same GUIDs, offsets, types and sizes |
| differing bytes in decompressed `FVMAIN` | \- | 505 | 0.0093% |
| modules differing by exactly 8 bytes | \- | 61 | DEBUG/LTO metadata drift |
| P2 marker set in probe PE | `P0/P1/P2` | `P0/P1/P2` | pass |
| virtual marker set in probe PE | absent | absent | pass |

The replay log also contains the exact physical-timer compile option:

```text
-DAVF_POST_EBS_USE_PHYS_TIMER
```

The remaining 17-byte difference in the probe application comprises a small
ARM64 code-generation/register-allocation delta plus debug data; it does not
change its physical-versus-virtual selection or its observable marker set.
The fresh full-FD SHA is therefore not a suitable reproducibility criterion
for this DEBUG/LTO build, while its source-level P2 identity is confirmed.

```text
P2_BITWISE_FIRMWARE_REPRODUCTION = FAIL
P2_SEMANTIC_SOURCE_REPLAY        = PASS
```

## Valid next control

The next valid runtime is not P2.1.  It is one bounded, firmware-only replay
of the fresh P2 source build using the existing reversible one-range pipeline.
It must reproduce the established `BES -> P0 -> P1` prefix before any P2.1
watchdog build may be interpreted.  It must change no Windows media, BCD,
Android code, ACPI table, or VM topology and must restore the immutable
baseline hash after rollback.
